# 게임 데이터 편집기 (기획자용)

병종 능력치·강화, 스켈레톤, 달·흡혈 규칙 수치, 장(지도·적·예시 편성·보상)은 코드가 아니라 데이터 에셋에 있다. 에셋을 고치면 다음 재생부터 게임이 그 값으로 돈다.

출처: docs/request/GameData_ScriptableObject_Editor_Request.md (요청 001, 이슈 #19)

## 여는 법

Unity 메뉴 `VampireSpawn > 도구 모음 (Tools)` 에서 **게임 데이터 편집기** 를 누른다.

## 화면

- **위 막대.**
  - **저장:** 고친 에셋을 디스크에 쓴다.
  - **HTML 기본값과 다른 곳:** 프로토타입(docs/Prototype.html) 값과 다른 줄만 보여 준다.
  - **고른 항목을 기본값으로**, **전체를 기본값으로:** 프로토타입 값으로 되돌린다. 묻고 나서 되돌린다.
- **문제 상자.** 데이터 전체를 늘 검사한다. 빨간 상자가 떠 있으면 게임은 이 데이터를 쓰지 않고 HTML 기본값으로 돈다(콘솔에도 같은 목록). 검사하는 것:
  - 지도 행 길이가 다르거나 모르는 칸이 있음
  - 뱀파이어가 하나가 아님
  - 적이 바위·물 위에 있음
  - 예시 편성이 배치 구역 밖에 있거나 그 장에서 못 쓰는 병종임
  - 칸이 겹침
  - id 가 겹침
  - 첫 장이 데모가 아님
  - 체력 0, 관 열림이 보름달보다 큼
- **왼쪽 목록.** 규칙, 적(스켈레톤), 병종 여섯, 장 열하나. 장을 고르면 **고른 장 복제** 로 새 장을 만들 수 있다.
- **오른쪽.** 고른 항목의 값. 장이면 위에 **지도 칠하기** 가 있다.
  - **칸 붓:** 평지 `.`, 바위 `#`, 화톳불 `T`, 물 `~`, 햇빛 `S`, 배치 구역 `d`.
  - **적 붓:** 스켈레톤, 뱀파이어. 뱀파이어는 한 마리라 새로 찍으면 이전 것이 지워진다.
  - **예시 붓:** 병종 글자. 배치 화면에 처음 놓이는 유닛이다.
  - **유닛 지우기**, **열·행 +/−.**
  - 칸을 누르거나 끌면 칠해진다. 실행 취소(Ctrl+Z)가 된다.

## 에셋 위치

| 무엇 | 에셋 |
|---|---|
| 전체 묶음 (씬이 참조) | `Assets/_Project/Data/GameData.asset` |
| 규칙 (흡혈 회복, 보름달, 흡혈 범위, 관 열림) | `Assets/_Project/Data/Rules.asset` |
| 스켈레톤 | `Assets/_Project/Data/Enemies/Skeleton.asset` |
| 병종과 그 강화 | `Assets/_Project/Data/Units/00_pspear.asset` … `05_hunter.asset` |
| 장 (0번 데모, 1~10 캠페인) | `Assets/_Project/Data/Stages/00_demo.asset` … `10_s10.asset` |

인스펙터에서 바로 고쳐도 되고, 편집기에서 고쳐도 된다. 같은 에셋이다.

## 조심할 것

- **id 는 바꾸지 않는다.** 강화 `id` 와 장 `id` 가 그렇다. 캠페인 저장이 id 로 산 강화와 클리어한 장을 기억한다. 바꾸면 플레이어 저장에서 그 기록이 사라진다. 병종 `key` 도 바꾸지 않는다.
- **병종 수는 고정이다.** 여섯이고 종류(`kind`)도 바꿀 수 없다. 새 병종은 코드 작업이 필요하다(모델·애니메이션 연결).
- **장 순서.** `GameData.asset` 의 `stages` 순서가 캠페인 순서다. 0번은 데모다. 병종의 `unlockAt` 은 이 순서의 장 번호를 가리킨다.
- **규칙 비교 시험은 데이터와 무관하다.** EditMode·PlayMode 의 HTML 비교 시험은 데이터 에셋이 아니라 HTML 값(`Core/PrototypeData.cs`)으로 돈다. 그래서 기획 값을 바꿔도 시험은 깨지지 않는다. 깨지면 규칙 코드가 바뀐 것이다.
- **데이터가 깨지면** `GameDataAssetTests.ShippedAssetsAreComplete` 가 실패한다. 커밋 전에 편집기의 문제 상자를 비운다.
- **기획서와의 관계.** 데이터 에셋은 데이터 기획서(`docs/content/`)를 구현한 것이다. CLAUDE.md "충돌" 대로 기획서와 에셋이 다르면 에셋을 기획서에 맞춘다. 편집기로 찾은 값을 남기려면 `docs/design/` 에 방향을 적거나 기획 에이전트에게 기획서 반영을 맡긴다. 에이전트는 docs/design 에 쓰지 않는다.
