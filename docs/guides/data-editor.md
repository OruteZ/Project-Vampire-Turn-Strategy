# 게임 데이터 편집기 (기획자용)

병종 능력치·강화, 하수인, 달·흡혈·치료 규칙 수치, 장(지도·적·예시 편성·보상)은 코드가 아니라 데이터 에셋에 있다. 에셋을 고치면 다음 재생부터 게임이 그 값으로 돈다.

출처: 요청 001, 이슈 #19

## 여는 법

Unity 메뉴 `VampireSpawn > 도구 모음 (Tools)` 에서 **게임 데이터 편집기** 를 누른다.

## 화면

- **위 막대.**
  - **저장:** 고친 에셋을 디스크에 쓴다.
  - **고른 항목 복제:** 고른 병종·하수인·장을 복제해 목록 끝에 더한다. 새 병종·하수인·장은 이렇게 만든다(아래 "새 병종·하수인 더하기").
- **문제 상자.** 데이터 전체를 늘 검사한다. 빨간 상자가 떠 있으면 게임이 바르게 돌지 않는다(콘솔에도 같은 목록). 검사하는 것:
  - 지도 행 길이가 다르거나 모르는 칸이 있음
  - 뱀파이어가 하나가 아님
  - 적이 바위·물 위에 있음
  - 장에 적은 병종·적 key 가 데이터에 없음
  - 예시 편성이 배치 구역 밖에 있거나 그 장에서 못 쓰는 병종임
  - 칸이 겹침
  - id·key 가 겹침
  - 첫 장이 데모가 아님
  - 체력 0, 관 열림이 보름달보다 큼, 치료 거리 0
- **왼쪽 목록.** 규칙, 하수인(스켈레톤·스켈레톤 궁수·스켈레톤 중갑병), 병종 여덟, 장 열하나.
- **오른쪽.** 고른 항목의 값. 장이면 위에 **지도 칠하기** 가 있다.
  - **칸 붓:** 평지 `.`, 바위 `#`, 화톳불 `T`, 물 `~`, 햇빛 `S`, 배치 구역 `d`.
  - **적 붓:** 뱀파이어와 하수인마다 하나. 뱀파이어는 한 마리라 새로 찍으면 이전 것이 지워진다. 적 목록 순서가 하수인 행동 순서다.
  - **예시 붓:** 병종 글자. 배치 화면에 처음 놓이는 유닛이다.
  - **유닛 지우기**, **열·행 +/−.**
  - 칸을 누르거나 끌면 칠해진다. 실행 취소(Ctrl+Z)가 된다.
- **문장 칸.** 오른쪽 맨 아래. 병종 이름·글자·설명, 강화 이름·설명, 하수인 이름·글자·카드 설명, 장 번호·제목·소개·보스 이름. 에셋이 아니라 문자열 표 `Text` 의 한국어 칸에 쓰인다(`Assets/_Project/Localization/Tables/`). 저장을 누르면 표도 저장된다. 영어는 `Window > Asset Management > Localization Tables` 에서 고친다(docs/ui/localization.md).

## 에셋 위치

| 무엇 | 에셋 |
|---|---|
| 전체 묶음 (씬이 참조) | `Assets/_Project/Data/GameData.asset` |
| 규칙 (흡혈 회복, 보름달, 흡혈 범위, 관 열림, 치료 거리) | `Assets/_Project/Data/Rules.asset` |
| 하수인 | `Assets/_Project/Data/Enemies/Skeleton.asset`, `SkeletonArcher.asset`, `SkeletonHeavy.asset` |
| 병종과 그 강화 | `Assets/_Project/Data/Units/00_pspear.asset` … `07_doctor.asset` |
| 병종·하수인 모습 (모델, 무기, 아이콘) | `Assets/_Project/Art/Units/*.asset` (UnitLook), `Assets/_Project/Art/ArtCatalog.asset` 의 `allyLooks`·`minionLooks` |
| 장 (0번 데모, 1~10 캠페인) | `Assets/_Project/Data/Stages/00_demo.asset` … `10_s10.asset` |

인스펙터에서 바로 고쳐도 되고, 편집기에서 고쳐도 된다. 같은 에셋이다.

## 새 병종·하수인 더하기

병종·하수인은 코드가 아니라 문자열 `key` 로 찾는다. 기존 기술·능력치로 되는 병종이면 코드 없이 더할 수 있다.

1. 편집기에서 비슷한 병종(하수인)을 고르고 **고른 항목 복제**. `key` 를 새 이름으로 고친다(영문, 저장·장 에셋이 이것으로 찾는다). 병종이면 강화 id 도 `<key>_...` 로 바뀐다.
2. 수치·등급·인구·은·해금 장(`unlockAt`)·기본 기술(`skills`)·강화 세 갈래를 고친다. `GameData.asset` 의 `units` 순서가 병영 탭·편성 목록 순서다.
3. 문장 칸에 이름·글자·설명(강화 이름·설명)을 쓴다. 영어는 Localization Tables 창.
4. 모습: `Assets/_Project/Art/Units/` 의 UnitLook 하나를 복제해 `key` 를 같게, 모델·무기·`icon`(Synty UI 스프라이트 이름)을 고르고, `ArtCatalog.asset` 의 `allyLooks`(하수인은 `minionLooks`)에 넣는다. 아이콘 스프라이트는 `ArtCatalog.ui` 에도 있어야 한다. Synty 참조가 바뀌면 `node tools/assets/scan.mjs`.
5. 장에서 쓰려면 그 장의 출전 병종(`units`)에 key 를 넣고, 하수인은 적 붓으로 찍는다.
6. 새 기술(`Ability`)이 필요하면 코드 작업이다(`Core/Battle*.cs`). `Ability` 는 에셋에 숫자로 저장되니 끝에만 더한다.

## 조심할 것

- **id 는 바꾸지 않는다.** 강화 `id` 와 장 `id` 가 그렇다. 캠페인 저장이 id 로 산 강화와 클리어한 장을 기억한다. 바꾸면 플레이어 저장에서 그 기록이 사라진다. 병종 `key` 도 바꾸지 않는다.
- **스폰 계승 표시는 계산된다.** 강화의 "스폰이 물려받음" 은 데이터에 적지 않는다. 체력·공격·이동만 더하는 강화가 물려받고, 방어·사거리·은탄·치료량·기술 강화는 물려받지 않는다(docs/systems/progression.md 15).
- **강화 목록 순서가 갈래 번호다(#99).** 병종마다 강화 3개 중 하나만 고른다. 1번은 물려받는 갈래로 둔다(docs/content/units.md 3절). 순서를 바꾸면 병영 줄 순서와 디버그 창 "갈래 받기" 번호가 바뀐다.
- **`key` 를 바꾸면** 그 key 를 적은 장 에셋·UnitLook·문장 키·플레이어 저장이 모두 끊긴다. 바꾸지 않는다.
- **장 순서.** `GameData.asset` 의 `stages` 순서가 캠페인 순서다. 0번은 데모다. 병종의 `unlockAt` 은 이 순서의 장 번호를 가리킨다.
- **규칙 시험은 지금 데이터로 돈다.** `Tests/EditMode/ExpansionRulesTests.cs` 등은 기대값을 데이터에서 읽으므로 수치를 바꿔도 대개 깨지지 않는다. 깨지면 규칙이 바뀌었거나 시험 장면(작은 지도)이 기대하는 성질(예: 궁수 사거리 2 이상)이 사라진 것이다.
- **데이터가 깨지면** `GameDataAssetTests.ShippedAssetsAreComplete` 가 실패한다. 커밋 전에 편집기의 문제 상자를 비운다.
- **기획서와의 관계.** 데이터 에셋은 데이터 기획서(`docs/content/`)를 구현한 것이다. CLAUDE.md "충돌" 대로 기획서와 에셋이 다르면 에셋을 기획서에 맞춘다. 편집기로 찾은 값을 남기려면 `docs/design/` 에 방향을 적거나 기획 에이전트에게 기획서 반영을 맡긴다. 에이전트는 docs/design 에 쓰지 않는다.
