## 1. 기준

1. 기준 해상도 **1920×1080**. CanvasScaler 는 Scale With Screen Size, Screen Match Mode **Expand** (15-1). Match 값은 쓰지 않는다.
   - 전투 화면만 예외 (#118): HUD 전체를 0.55 배로 그린다 (`BattleFlow.HudZoom`, 전투 전용 PanelSettings 사본의 기준 해상도 3491×1964). 전투 HUD 의 px 은 그 판 기준이고 화면에선 ×0.55, 글자 하한은 화면 14px (판 기준 26px). 자세한 값은 docs/ui/battle-hud.md 1.
2. 화면 가장자리 안전 여백 **24px**. 이 안에만 UI 를 둔다.
3. 보드 영역: 위 **150px**, 아래 **190px**, 왼쪽·오른쪽 **360px** 를 뺀 가운데. 전투 화면 UI 는 보드 영역을 가리지 않는다. 툴팁·미리 보기·머리 위 표시만 예외다.
4. 모든 수치는 1920×1080 기준 px 이다.

### 2-2. 진영 규칙

1. **한 패널에는 한 진영 색만** 쓴다. 아군 패널은 `ally`, 적 패널은 `enemy`, 스폰 패널은 `spawn`.
2. 진영이 없는 정보(턴 수, 규칙, 메뉴)는 `ally` 틀을 쓴다. 이 게임의 화면은 토벌대의 것이다.
3. 적 색 `enemy` 는 적 정보에만 쓴다. 아군 패널의 위험 경고(보름달 표적, 체력 낮음)도 `enemy` 글자로 쓰되 틀은 아군 틀 그대로 둔다.
4. `light` 는 진영이 아니다. 광원·재화에만 쓴다.

## 3. 중요도 3단계 (ui.md "중요도 차등")

| | 1단계: 지금 결정 | 2단계: 참고 | 3단계: 배경 |
|---|---|---|---|
| 무엇 | 선택 유닛·호버 대상의 체력·이동력·공격력, 피해 미리 보기, 보름달 게이지, 턴 종료 | 전황 수치(턴·아군·적·스폰), 전투 기록 최근 3줄, 패널 안 부가 수치(사거리·방어) | 규칙 요약, 안내 문구, 전투 기록 지난 줄 |
| 글자 | `num.1` / `h.2`, `text.1` | `body`, `text.2` | `small`, `text.3` |
| 틀 | 진영 색 틀, 밝은 상태 | 장식 없는 얇은 틀 또는 틀 없음 | 틀 없음, 접혀 있음 |
| 자리 | 화면 아래 모서리·위 가운데 | 화면 위 모서리 | 버튼을 눌러야 펼침 |
| 움직임 | 바뀌면 0.2초 번쩍임 | 없음 | 없음 |

- 한 화면에 1단계 요소가 동시에 **5개를 넘지 않게** 한다. 넘으면 화면별 기획서에서 하나를 2단계로 내린다.

## 7. 보름달 게이지

### 7-1. 모양

1. 화면 위 가운데. `Frame_Ring_01` 지름 **112px**, 위 여백 24px.
2. 원 안은 달의 위상. 어두운 원(`bg.panelDeep`) 위에 오른쪽부터 밝은 면(`moon`)이 Moon/MoonMax 만큼 찬다: 0 은 그믐(빈 원), 반은 반달, MoonMax 는 보름달(꽉 찬 원). 그 사이는 초승달·상현 너머 볼록달처럼 명암 경계가 둥글게 휜다. 칸으로 나누지 않는다(#118, 사용자 "피자처럼 차는게 별로, 달 느낌").
3. 원 아래에 `num.2` 로 "달 {Moon}/{MoonMax}", 그 아래 `small` `text.2` 로 상태 한 줄:
   - 뱀파이어가 잠들어 있으면 "{MoonWake}에 관이 열림"
   - 다음 적 턴이 보름달이면 "다음 턴 보름달" (`moon.blood`)
   - 그 밖에는 비움
4. 관이 열리는 시점은 3 의 상태 줄 글자로만 알린다(칸 경계가 없어 관 표시 막대는 뺐다).

### 7-2. 단계별 변화

| 상태 | 게이지 | 화면 가장자리 |
|---|---|---|
| 달 < MoonMax − 1 | 밝은 면 `moon` | 없음 |
| 다음 적 턴이 보름달 | 밝은 면이 `moon.blood` 로, 1.2초 주기로 밝기 ±10% 맥박 | 화면 네 가장자리에 `moon.blood` 비네트, 불투명도 8%, 폭 80px |
| 보름달 턴 (적 턴 중) | 전부 `moon.blood`, 둘레에 `Greeble_DemonSkull` 4개 | 비네트 15% |
| 보름달이 지나 0 으로 | 0.4초에 걸쳐 핏빛 보름달이 사라짐 | 비네트 0.4초에 사라짐 |

- 비네트 불투명도는 화면에 보이는 값이다. 선형 색 공간에서 섞이면 진해 보이니, 구현은 스크린샷으로 맞춘다.
- 보름달 표적 아군: 머리 위에 `Status_Targeted_01` 32px `enemy` 색, 칸 테두리 `enemy`. 이것이 이 게임의 유일한 행동 예고다 (combat.md, vampire.md).

## 8. 보드 위 표시

### 8-1. 머리 위 체력

1. 유닛 머리 위에 체력 칸 막대. 막대 길이는 최대 체력과 상관없이 늘 72px, 높이 12px (호버 때 겹치는 14px 숫자가 막대 밖으로 나오지 않는 높이). 칸 하나 = 체력 1 이고 최대 체력이 클수록 칸이 좁아진다. 칸 사이 경계는 1px `bg.ink` 55% 선 (칸을 띄우지 않는다). 평소에는 숫자를 붙이지 않는다 (3).
2. 찬 칸 색: 아군 `ally`, 적 `enemy`, 스폰 `spawn`. 빈 칸 `bg.panelDeep`.
3. 평소에는 칸 막대와 7 의 방패만. 호버하거나 선택한 유닛만 막대 위에 이름(`small`)만, 체력 "{hp}/{max}" 은 막대 위에 겹쳐 가운데에 14px Bold `text.1`, 1px `bg.ink` 외곽선 (#110). 이 유닛의 머리 위 표시는 다른 유닛 것보다 위에 그린다.
4. 바탕은 `HUD_DarkFantasy_WorldSpace_NameAlly_01` / `NameEnemy_01` 에서 이름 칸을 끄고 막대만 남겨 쓴다.
6. 보드 위에 글자 라벨(예: "다음 턴 보름달", "보름달 표적")을 두지 않는다. 같은 정보는 보름달 게이지 상태 줄, 표적 아이콘, 아군 패널 경고 줄이 준다.
7. 방어가 1 이상인 유닛만 체력 막대 가운데에 `Status_Defense_01_Stroke` 16px `text.1` 방패를 방어 수만큼 붙여 그린다 (방패 아래쪽 30% 가 막대에 걸침, 간격 −3px). 방어 0 이면 막대만. 공격은 보드에 표시하지 않는다 (패널에만). 가로 폭을 늘리지 않으려는 것이다.

### 8-2. 칸 표시

| 표시 | 모양 |
|---|---|
| 이동 가능 칸 | 칸 테두리 `ally` 2px, 안쪽 채움 `ally` 8% |
| 공격 가능 대상 칸 | 칸 테두리 `enemy` 2px |
| 호버 칸 | 테두리 `text.1` 2px |
| 보름달 표적 칸 | 7-2 |
| 직접 처치 가능한 아군 칸 | 테두리 `enemy` 점선 |
| 흡혈 범위 칸 (다음 적 턴이 보름달일 때만) | 테두리 `moon.blood` 1px 실선, 안쪽 채움 `moon.blood` 5% |
| 광원 칸 | UI 로 덧칠하지 않는다. 보드 아트(docs/areas/art-assets.md)가 이미 보인다 |

### 8-3. 피해 미리 보기 (ui.md "계산 도움")

공격 대상을 호버하면:
1. 대상 머리 위 막대에서 잃을 칸이 0.5초 주기로 깜빡인다.
2. 막대 오른쪽에 `num.2` 로 "−{피해}", `enemy` (아군이 맞으면) 또는 `text.1` (적이 맞으면).
3. 처치되면 숫자 대신 `Status_Dead_01` 24px.
4. 그 처치로 스폰이 생기면 `Status_Vampiric_01` 24px `spawn` 을 하나 더. 확률 표시는 없다 (overview.md 무작위 없음).

### 8-4. 적 이동력 한꺼번에 보기

1. **Alt 키를 누르는 동안** 모든 적 머리 위 막대 위에 이동력 숫자를 `num.2` `enemy` 로, `Stat_Speed_01` 아이콘 20px 과 함께 보인다.
2. 위험한 칸을 칠해 주지는 않는다. 플레이어가 이 숫자로 스스로 센다 (ui.md "위협 범위는 직접 제공하지 않는다").
3. 지금 데모의 "적 위협 범위" 체크박스를 이것으로 바꾼다. 적을 살펴볼 때 칠하던 위협 칸과 그 안내 문구도 없앤다.

### 8-5. 보스 머리 위 체력 (#110)

뱀파이어(보스)의 체력은 화면 위 막대가 아니라 머리 위에서만 보인다. 모양만 다른 유닛과 다르게 그린다 (ui-references.md 5-8, Gloomhaven 의 보스 받침).

1. 대상: 뱀파이어 하나. 관에 누워 잠든 동안은 다른 누운 유닛처럼 머리 위 표시가 없고(체력은 적 패널), 깨어난 뒤부터 보인다. 하수인·스폰은 8-1 그대로.
2. 막대: 120×16px (다른 유닛 72×8). 보스 체력이 13~42 라 72px 칸 막대로는 칸이 2px 아래로 떨어져 읽히지 않는다.
3. 칸으로 나누지 않고 이어진 채움 `enemy`, 빈 부분 `bg.panelDeep`. 체력 5 마다 1px `bg.ink` 55% 눈금 (몇 대 남았는지 셀 수 있게).
4. 틀: `frame.boss` (`Frame_Bar_Medium_01`, `enemy`) 를 막대 바깥에 두르고, 틀 굵기는 화면에서 3px. 바탕은 8-1 4 와 같은 어두운 판.
5. 막대 왼쪽 끝에 `Greeble_DemonSkull_01` 28px `enemy` 를 세로 가운데 맞춰 걸친다 (막대 안쪽으로 10px). 보드 위 악마 장식은 이것 하나다.
6. 숫자는 8-1 3 과 같다: 평소에는 없고, 호버·선택하면 막대 안 가운데에 "{hp}/{max}".
7. 호버·선택하면 막대 위에 이름 `small` 만. 8-1 3 처럼 다른 유닛 표시보다 위에 그린다.
8. 방어 방패(8-1 7): 숫자를 가리지 않게 막대에 걸치지 않고, 막대 위 변에 바닥을 붙여 가운데에 놓는다. 이름은 그 위로 올라간다.
9. 피해 미리 보기(8-3): 칸 대신 잃을 길이만큼의 채움 조각이 0.5초 주기로 깜빡인다. "−{피해}"·처치 아이콘은 8-3 그대로 막대 오른쪽.
10. 맞는 연출: 다른 유닛처럼 채움 길이가 맞는 연출의 체력(`UnitView.HpFraction`)을 따라 줄고, 숫자는 새 값으로 바뀌며 0.2초 번쩍인다 (3절 1단계 움직임).

## 14. 글보다 그림 (2026-11-07 개편, #33)

사용자 원문(#33): "불필요한 미사여구와 부연설명 하는 작은 글씨 … 전부 쳐내고 … 데스페라도스 스테이지 진입처럼 글보단 그림과 아이콘이 주가". 레퍼런스: ui-references.md "Desperados III 화면 읽기". 아래 규칙이 1~13절과 화면별 기획서(docs/ui/*.md)보다 앞선다.

### 14-1. 글 예산

1. 화면에 남는 글은 **이름(장·유닛·강화·버튼)과 숫자**뿐이다. 문장(마침표로 끝나는 줄)은 규칙 요약 창 말고는 화면에 두지 않는다.
2. 설명이 필요한 것은 **툴팁**(HoverTip, 0.5초)으로 옮긴다. 지우지 않고 옮긴다. 장 소개(Brief), 강화 설명(Desc), 유닛 노트, 메뉴 카드 설명이 여기 간다.
3. 항목 이름표("목표", "보상", "자원", "적", "체력", "이동" 같은 라벨)는 **아이콘으로 바꾼다**. 라벨 글자는 툴팁으로.
4. 머리말 위 작은 회색 "캠페인", "N장" 같은 이중 머리말은 없앤다. 장 번호는 번호 배지(14-3)로.
5. 상태 낱말("클리어", "열림", "잠김", "보유")은 아이콘 상태로 바꾼다: 클리어 ✓ 원, 열림 맥박 원, 잠김 자물쇠, 보유 ✓.
6. 보드 아래 안내 문구는 배치 단계와 아군 처치 모드에서만 둔다(그 모드의 유일한 피드백). 다른 때는 없앤다. 게이지 아래 "N에 관이 열림"은 관 눈금이 눈에 띄지 않아 남긴다(방향 검토).
7. 경고 줄(표적·빛·변이·시신)과 버튼 낱말은 문장이어도 남긴다. 1단계 정보다.
8. 강화 효과(Desc)는 사기 전에 꼭 봐야 하므로 강화 칸에 남긴다(방향 검토).
9. Alt 이동력 보기를 알 수 있게 전황 줄 끝에 `Alt` 키 칸 + 이동력 아이콘을 늘 둔다.

## 15. 고정 크기 — 적응형 비율 없음 (#43)

사용자 원문(#43): 게임에서 요소와 버튼 하나하나가 해상도에 따라 커졌다 작아지는 것은 비정상적으로 보인다. 레퍼런스: ui-references.md 2-5. 15·16절이 1~14절과 화면별 기획서보다 앞선다. 모든 화면에 걸린다.

### 15-1. 캔버스는 한 비율로만

1. CanvasScaler: Scale With Screen Size, 기준 1920×1080, Screen Match Mode = **Expand**. 캔버스는 1920×1080 보다 작아지지 않고, 남는 쪽 축만 늘어난다. UI Toolkit `PanelSettings`(`Assets/_Project/UI/Panel.asset`)도 같은 값(Scale With Screen Size, 1920×1080, Expand)이다. 두 UI 가 한 화면에서 같은 px 로 맞아야 한다.
2. 화면 전체가 한 비율로 커지고 작아진다. 칸·글·아이콘을 따로 키우지 않는다.
3. 화면비별 캔버스 (검사 6개 화면비, docs/dev/ui-audit.md):

| 화면 | 비율(배율) | 캔버스 (px) | 늘어난 쪽 |
|---|---|---|---|
| 1920×1080 | 1.0 | 1920×1080 | 없음 |
| 1280×720 | 0.667 | 1920×1080 | 없음 |
| 1920×1200 | 1.0 | 1920×1200 | 위아래 +120 |
| 1440×1080 | 0.75 | 1920×1440 | 위아래 +360 |
| 1280×1024 | 0.667 | 1920×1536 | 위아래 +456 |
| 2560×1080 | 1.0 | 2560×1080 | 옆 +640 |

4. 그래서 1920×1080 에 맞춘 배치는 6개 화면비 모두에 그대로 들어간다. 늘어난 쪽은 가운데 게임 화면이 더 보이는 자리다. 모서리 칸은 모서리에 붙어 따라간다.
5. 16:9 보다 좁은 화면(16:10·4:3·5:4)에서는 화면 전체가 폭에 맞춰 작아진다(배율 = 화면 폭 / 1920). 720p 와 같은 크기라 최소 글자 14px(4절)도 720p 와 같은 크기로 보인다.

### 15-2. 크기와 앵커

1. 패널·버튼·글 칸·아이콘은 이 문서와 화면 기획서에 적은 **px 고정 크기**다. 화면 크기·남은 폭·남은 높이로 크기를 계산하지 않는다.
2. 앵커는 **한 점**(anchorMin = anchorMax)이다. 9자리(네 모서리, 네 변 가운데, 화면 가운데) 중 하나에 두고, 그 점에서 px 로 띄운다. 안전 여백 24px(1-2)은 그대로.
3. 쓰지 않는 것:
   - 화면에 붙은 stretch 앵커 (anchorMin ≠ anchorMax 인 패널·버튼·글)
   - 화면 남은 폭·높이를 채우는 칸 (지금 병영 칸 "남은 폭", 원정 길 칸 "머리 아래 끝까지")
   - 화면 크기를 따라가는 LayoutElement flexible·childForceExpand
   - 글 크기 자동 줄이기 (Best Fit)
4. 레이아웃 그룹은 고정 크기 자식을 줄 세울 때만 쓴다. 부모 칸이 고정 크기이면 그 안의 flexible(남은 폭 나누기)은 써도 된다. 결과가 고정이기 때문이다.
5. 내용이 칸보다 길면 칸은 커지지 않는다. 목록은 칸 안에서 스크롤한다. 글은 정한 줄 수 안에서 줄바꿈하고, 그래도 넘치면 번역을 줄인다 (docs/ui/localization.md 27·28).
6. 버튼 크기는 화면 기획서에 px 로 적는다. 상태가 바뀌어도(예: "강화" → "정말 살까요?") 크기는 그대로다. 글이 버튼을 넘으면 번역을 줄인다 (docs/ui/localization.md 26~28, 그 26번의 "글 길이만큼 넓어진다" 를 #43 에서 고정 크기로 고쳤다).

### 15-3. 예외 (정말 필요한 것만)

| 예외 | 왜 |
|---|---|
| 바탕 층: 3D 화면, 메뉴의 흐린 보드, 가장자리 그늘·비네트(7-2), 팝업 뒤 어두운 막 | 화면 전체를 덮는 것이 할 일이다. 그리는 것은 색·그림뿐, 버튼·글이 없다 |
| 보이지 않는 뿌리 노드 (Screen, Hud, 레이어 노드, OverRoot) | 좌표 뿌리다. 그리지 않는다 |
| 보드 영역 (BoardArea, 1-3) | 3D 카메라 틀을 잡는 보이지 않는 사각형. 그리지 않는다 |
| 고정 크기 칸 안에서 그 칸을 채우는 자식 (틀 스프라이트, 칸 배경, 버튼 글) | 부모가 고정이라 결과가 고정이다 |
| 세상 위 표식 (머리 위 체력 8-1, 지도 지역 표식) | 크기는 px 고정, 자리만 3D 점을 따라간다 |

### 15-4. 지금 코드에서 바꾸는 것

1. `GameFlow.BuildCanvas`: `matchWidthOrHeight = 0.5` → `screenMatchMode = Expand`. `Assets/_Project/UI/Panel.asset` 도 맞춤 0.5 → Expand.
2. `CampaignScreen`: 원정 길·장 정보 칸(세로 stretch), 병영 칸(가로·세로 stretch), 강화 칸 flexible → docs/ui/stage-select.md, docs/ui/upgrade.md 의 고정 칸으로 다시 짠다. 칸·버튼은 UI Toolkit(UXML/USS)으로, 지역 표식은 uGUI 로 짓는다 (stage-select.md 10절).
3. 다른 화면(전투, 메인 메뉴)은 이미 모서리·가운데 고정 칸이다. Expand 로 바꾼 뒤 `tools/ui-audit/sweep.sh` 를 모든 화면에 다시 돌려 확인만 한다 (battle-hud.md, main-menu.md 의 "후속").

## 16. 화면 배치 원칙 (#43)

사용자 원문(#43): UI 가 화면을 다 채우지 않고, 게임 요소가 늘 가운데 보이고, UI 정보는 중요하거나 특정한 상황이 아니면 사이드에. 레퍼런스: ui-references.md 3절.

### 16-1. 가운데는 게임

1. 화면 가운데는 3D 세상(보드, 원정 지도)이 차지한다. UI 는 네 모서리와 네 변에 붙는다.
2. 한 레이어에서 UI 칸이 덮는 넓이의 합은 1920×1080 화면의 **30% 이하**다. 16-2 의 순간은 뺀다.
3. 3D 카메라는 UI 칸을 뺀 남은 사각형(빈 곳)의 가운데에 보여 줄 것을 둔다. 빈 곳이 바뀌면(칸이 열리고 닫히면) 0.3초에 걸쳐 따라간다 (12절 화면 전환).

### 16-2. 가운데 UI 는 특정한 순간만

| 순간 | 화면 | 모양 |
|---|---|---|
| 전투 결과 | battle-hud.md | 고정 크기 창, 뒤 보드가 보인다 |
| 되돌릴 수 없는 일의 확인 | `frame.popup` | 고정 크기 |
| 규칙 요약 창 | battle-hud.md | 고정 크기 720 폭 |
| 보름달 게이지 | 전투 | 위 변 가운데. 화면 상징이라 1단계 자리 |

- 이 밖에는 가운데에 칸을 두지 않는다. 메인 메뉴의 카드 둘은 고를 것이 그것뿐인 화면이라 가운데에 둔다 (main-menu.md).

### 16-3. 자리 규칙

| 자리 | 무엇 | 예 |
|---|---|---|
| 왼쪽 위 | 화면 이름 + 뒤로 (Esc) | 장 선택 "토벌 원정" + 메인 메뉴 |
| 위 가운데 | 화면 상징 하나 | 보름달 게이지 |
| 오른쪽 (위에 붙임) | 고른 것의 상세 칸 (오른쪽 칸) | 장 정보, 병영, 전투 기록 |
| 왼쪽 아래 | 다른 레이어로 가는 버튼, 내 쪽 정보 | 병영 버튼, 아군 패널 |
| 오른쪽 아래 | 이 레이어의 주 행동. 오른쪽 칸이 있으면 그 칸 안 오른쪽 아래. 전투 화면만 예외로 아래 가운데 원형 버튼 (#118) | 출정(장 정보 칸 안) |

1. 모서리 하나에는 덩어리 하나만 둔다.
2. 같은 일을 하는 버튼은 레이어가 바뀌어도 같은 자리다.
3. 고른 것의 상세는 오른쪽 칸 하나다. 다른 것을 고르면 그 칸의 내용이 바뀌고 칸은 그대로다.

### 16-4. 레이어

1. 한 화면을 여러 레이어로 나눈다. 레이어마다 할 결정이 하나다 (장 선택: 지도에서 장 고르기 → 장 정보에서 출정 → 병영에서 강화).
2. 레이어가 바뀌면 오른쪽 칸 내용과 카메라만 바뀐다. 모서리 버튼은 그대로다.
3. Esc 는 한 레이어 뒤로 간다. 맨 앞 레이어에서 Esc 는 앞 화면으로 간다.
4. 패널이 열리고 닫히는 움직임은 12절(0.15초), 카메라는 0.3초.

### 16-5. 정보는 필요한 레이어에만

1. 재화·수치는 그 레이어의 결정에 쓰일 때만 보인다. 예: 장 선택 화면 안에서 가진 금화는 병영에서만 (금화는 강화를 살 때만 쓴다). 메인 메뉴 캠페인 카드의 금화는 "이어 하기" 요약이라 남긴다 (main-menu.md).
2. 다른 레이어에는 "할 수 있는 일이 있다"는 신호만 둔다. 예: 병영 버튼의 "살 수 있는 강화 수" 배지.
3. 진행(클리어·추가 목표)은 세상 위에 둔다. 예: 지도 지역 표식의 상태와 ★.

## 정한 세부 (docs/design 에 없는 것)

- **CanvasScaler 는 Expand (15-1).** 근거: 사용자가 칸이 따로 커지고 작아지는 것을 싫어했고, 칸은 고정 크기로 모서리에 붙였다. 이때 캔버스가 기준보다 작아지면 칸끼리 겹친다. Match 0.5(지금)는 21:9 에서 캔버스 높이가 935, 5:4 에서 폭이 1610 으로 준다. Match 1(높이 맞춤)은 5:4 에서 폭이 1350 이라 전투 화면 아래 줄(아군 패널 364 + 행동 줄 400 + 적 패널·턴 종료 580)이 겹친다. Expand 는 16:9 이상에서는 Match 1 과 같고(21:9 는 세상이 옆으로 더 보인다), 16:9 보다 좁으면 Match 0 과 같다. 1920×1080 에 맞춘 배치가 늘 들어간다. 대가는 4:3·5:4 에서 UI 가 화면 높이에 비해 작아지는 것이다(720p 와 같은 크기).
- **UI 칸 넓이 30% 이하 (16-1).** 근거: 사용자 원문 "UI 요소가 화면을 전부 채우도록 하지 않고". 숫자로 잴 수 있어야 검사할 수 있다. 장 정보 레이어(오른쪽 칸 560×520 + 왼쪽 위 480×64 + 왼쪽 아래 240×56)가 약 16%, 병영 레이어(560×680 …)가 약 21%, 지금 전투 화면이 약 13% 다. 30% 는 지금 개편 전 장 선택 화면(약 85%)과 확실히 갈리는 선이다.
- **오른쪽 칸 = 상세, 왼쪽 위 = 뒤로 (16-3).** 근거: Civilization VI 가 고른 것의 목록을 오른쪽에 연다. 전투 화면에서도 적·기록이 오른쪽이다. 뒤로는 소녀전선 2 처럼 왼쪽 위, 키는 Esc.
- **글은 툴팁으로 옮기고 지우지 않는다 (14절).** 근거: ui.md "중요한 정보와 아닌 정보를 구분"과 "정보는 최대한 깔끔하게". 규칙·적 스펙 공개(ui.md "공개할 정보")는 툴팁·규칙 창에 그대로 남는다.
- **기준 해상도 1920×1080.** 근거: PC 패키지 게임의 가장 흔한 해상도. 지금 1600×900 은 HTML 데모 크기였다.
- **보름달 칸 수 = `Rules.MoonMax`.** 근거: 지금 규칙(적 턴·죽음마다 1, MoonMax 에서 보름달)을 그대로 보이게 한다. 수치가 바뀌어도 UI 가 따라간다.
- **적 위협 범위 체크박스를 Alt 이동력 보기로 바꾼다(8-4).** 근거: ui.md "위협 범위는 직접 제공하지 않는다", "플레이어가 위험한 타일을 스스로 계산할 수 있어야 한다". 이동력 숫자는 ui.md 가 공개하라고 한 스펙이다.
- **스폰 패널은 원래 병종 이름 + "스폰" 을 쓴다** (예: "기사 · 스폰"). 근거: units.md 의 "원본의 공격력과 체력을 계승"과 vampire.md 의 "주력 유닛일수록 더 강한 적"을 패널에서 바로 읽게 한다. 초상은 보드 모델이 이미 원래 병종이라 따로 두지 않는다.
- **1단계 요소 동시 5개 이하.** 근거: ui.md "많은 정보가 한 화면에 있더라도, 중요도 차등에 따라 분리되어 보이게". 하나의 화면에서 첫눈에 구분되는 강조는 몇 개를 넘으면 다 같아 보인다.
- **최소 글자 14px.** 근거: 1080p 모니터에서 한글 명조·고딕이 뭉개지지 않는 크기.
