> 출처: docs/design/campaign.md, docs/design/ui.md, docs/design/art.md, docs/design/overview.md (커밋 f7fc7f8). 요청 docs/request/UI 대개편 - 스테이지 선택.md (#43)

> 함께 보는 기획서: docs/art/campaign-map.md (3D 지도), docs/ui/upgrade.md (병영 레이어), docs/ui/battle-hud.md (출정하면 가는 배치 화면)
> 레퍼런스: docs/art/ui-references.md 2-1, 2-2 (Desperados III 임무 지도, Civilization VI 옆 칸, 파이어 엠블렘 인게이지 지도)
> 목적: 캠페인 화면에서 장을 고르고, 장 정보를 보고, 출정하거나 병영으로 가는 흐름을 정한다.

사용자 원문(#43, 줄임): 한 화면에 장 목록·유닛 강화·가진 돈을 다 펼친 웹사이트 같은 배치라 모델링 같은 게임 요소가 안 보인다. 장 선택을 여러 레이어(1. 스테이지 전경 2. 고르면 보이는 목표 설명과 시작 버튼 3. 병사 강화창으로 가는 버튼)로 나누고, 자원·정보는 필요할 때만 보인다.

## 1. 레이어

| 레이어 | 할 결정 | 오른쪽 칸 | 카메라 (campaign-map.md 9) | 지역 표식 |
|---|---|---|---|---|
| L1 지도 | 어느 장을 볼까 | 없음 | 전경 | 10개 모두 |
| L2 장 정보 | 이 장에 출정할까 | 장 정보 칸 (3절) | 지역 (고른 장) | 빈 곳 안에 든 것 |
| L3 병영 | 무엇을 강화할까 | 병영 칸 (docs/ui/upgrade.md) | 야영지 | 숨김 |

- 세 레이어 모두 같은 화면(`GameFlow` 의 camp)이다. 바탕은 늘 3D 원정 지도다. 레이어가 바뀌면 오른쪽 칸과 카메라만 바뀐다 (ui-style.md 16-4).
- 흐름: L1 → (지역을 누름) → L2 → (출정) → 전투 배치. 병영 버튼으로 L1·L2 어디서나 L3. Esc 는 한 레이어 뒤로.

기준 1920×1080, 안전 여백 24px. 모든 칸은 고정 크기, 한 점 앵커 (ui-style.md 15).

### 2-3. 빈 곳 (카메라가 보여 줄 곳)

카메라가 보여 줄 것(전경의 지역들, 고른 지역, 야영지)을 이 사각형 가운데에 둔다 (ui-style.md 16-1, campaign-map.md 9). 캔버스 px, 화면 가장자리에서:

| 레이어 | 왼쪽 | 위 | 오른쪽 | 아래 |
|---|---|---|---|---|
| L1 | 24 | 112 | 24 | 104 |
| L2, L3 | 24 | 112 | 608 (= 24 + 560 + 24) | 104 |

- 1920×1080 의 L2 빈 곳은 1288×864 다. 5:4(캔버스 1920×1536)에서는 1288×1320, 21:9(2560×1080)에서는 1928×864 다. 칸 크기는 그대로이고 빈 곳만 달라진다.

표식은 화면 UI 다(3D 물체가 아니다). 크기는 px 고정이고, 자리만 지역의 3D 점(앵커 + 표식 높이, campaign-map.md 4-1)을 매 프레임 따라간다 (ui-style.md 15-3 "세상 위 표식").

### 4-3. 그리기·숨기기

1. 먼 표식(화면 위쪽)부터 그리고 가까운 것을 위에 그린다. 가리킴·초점·고름 표식은 맨 위에.
2. 표식 가운데가 그 레이어의 빈 곳(2-3) 밖이면 그 표식을 숨긴다(그리지 않고 누를 수 없다). 카메라 뒤도 숨긴다. 그래서 칸·버튼과 겹치거나 화면 밖으로 나가지 않는다.
3. L3 에서는 모든 표식을 숨긴다.
4. 전경(L1)은 10개가 모두 빈 곳 안에 들도록 카메라가 맞춘다 (campaign-map.md 9).

## 5. 전환과 조작

### 5-1. 전환

| 지금 | 입력 | 다음 | 움직임 |
|---|---|---|---|
| 메인 메뉴 | 캠페인 카드 | L1 (초점 5-3) | 0.3초 검은 화면에서 밝아짐 |
| L1 | 표식 누름, 또는 Enter (초점 장) | L2 (그 장) | 칸 나타남 0.15초, 카메라 전경 → 지역 0.3초 |
| L2 | 다른 표식 누름, ↑/↓ | L2 (다른 장) | 칸 내용만 바뀜, 카메라 0.3초 옮김, 스폿광 옮김 |
| L2 | 닫기, Esc, 지도의 빈 땅 누름(UI 가 아닌 곳) | L1 (초점 = 그 장) | 칸 사라짐 0.15초, 카메라 지역 → 전경 0.3초 |
| L2 | 출정, Enter (열린 장) | 전투 배치 | 0.3초 검게 |
| L1, L2 | 병영 버튼, B | L3 | 칸 바뀜, 카메라 → 야영지 0.3초 |
| L3 | 닫기, Esc, B, 병영 버튼 | 온 레이어 (L1 또는 L2, 같은 장) | 칸 바뀜, 카메라 0.3초 |
| L1 | 메인 메뉴 버튼, Esc | 메인 메뉴 | 0.3초 검게 |

- L3 에서 지도를 눌러도 아무 일이 없다 (실수로 닫히지 않게).
- 진행 초기화가 확인 상태일 때 다른 곳을 누르거나 2.5초가 지나면 원래대로 돌아간다 (지금과 같다).

### 5-2. 키

| 키 | L1 | L2 | L3 |
|---|---|---|---|
| ↑ / ↓ | 초점을 다음 장(↑, 지도에서 북쪽) / 앞 장(↓)으로. 끝에서 멈춘다 | 고른 장을 다음 / 앞 장으로 | 없음 |
| ← / → | 없음 | 없음 | 병종 탭 (upgrade.md) |
| Enter | 초점 장의 L2 를 연다 | 열린 장이면 출정 | 없음 |
| Esc | 메인 메뉴 | L1 | 온 레이어 |
| B | L3 | L3 | 온 레이어 |

### 5-3. 처음 레이어와 초점

1. 메인 메뉴에서 들어오면 L1. 초점은 이번 실행에서 마지막에 고른 장, 없으면 "처음 고른 장" 규칙: 열렸지만 아직 클리어하지 않은 장 가운데 첫 장, 다 클리어했으면 마지막 장 (지금 `CampaignScreen.DefaultStage`).
2. 전투에서 돌아오면 (결과 창의 캠페인으로, 또는 나가기):
   - 그 전투로 처음 클리어해서 새 장이 열렸으면 L1, 초점은 새로 열린 장. 길이 밝아지고 화로가 켜진 것이 보인다.
   - 그 밖에는 L2, 그 장. 바로 다시 출정할 수 있다.
3. 진행 초기화 뒤에는 지도를 다시 짓고 L1, 초점 1장.

## 10. 어느 UI 로 짓나 (UI Toolkit + uGUI)

사용자 결정(#43): "개발을 UI Toolkit + UGUI로". #44 시험(docs/dev/ui-toolkit-trial.md 6 "새로 만들거나 크게 고치는 화면부터 UI Toolkit, 보드 위에 뜨는 것은 uGUI")을 따른다.

| 요소 | UI | 이유 |
|---|---|---|
| 머리(메뉴 버튼·"토벌 원정"), 진행 초기화, 병영 버튼 | UI Toolkit | 고정 칸. 배치 숫자를 USS 한곳에 둔다 |
| L2 장 정보 칸, L3 병영 칸 (upgrade.md) | UI Toolkit | 같다. 레이어 전환은 칸 클래스만 바꾼다 |
| 툴팁 | UI Toolkit (`MenuToolkit.Tip` 를 공용으로) | 런타임 UI Toolkit 은 tooltip 을 안 띄운다 (ui-toolkit-trial.md 4) |
| 지역 표식 (4절) | uGUI | 매 프레임 3D 점을 따라간다. 전투의 머리 위 표시와 같은 방식 |
| 가장자리 그늘, 0.3초 검은 화면 | uGUI 또는 UI Toolkit, 구현이 고른다 | 화면 전체 바탕 |

1. 그리는 순서: 3D 지도 → uGUI 표식 → UI Toolkit 칸 (`PanelSettings.sortingOrder` 가 uGUI Canvas 보다 위). 표식이 칸 아래로 들어가도 4-3 의 "빈 곳 밖이면 숨김" 이 겹침을 막는다.
2. 지도 클릭(빈 땅 → L1)은 uGUI 와 UI Toolkit 어느 쪽에도 포인터가 없을 때만 받는다.
3. 칸 크기·자리(2-2, 3-1, upgrade.md 3)는 USS px 로 그대로 옮긴다. UI Toolkit 글자는 같은 값에서 약 10% 크다(ui-toolkit-trial.md 4). 글자 크기만 맞추고 칸 크기는 바꾸지 않는다.
4. 이 화면의 `UiTextParityTests` 는 UI Toolkit 요소(Label)와 uGUI 표식을 함께 본다. `UiAudit.ToolkitReport` 로 6개 화면비 검사를 한다 (9절).
5. Synty 장식 프리팹(Crest, Section_Break)은 `MenuToolkit.Prefab` 처럼 VisualElement 로 다시 쌓는다. 그림은 USS `url()` 이 아니라 C# 에서 `ArtCatalog` 이름으로 넣는다 (scan.mjs 가 참조를 보게).

## 정한 세부 (docs/design 에 없는 것)

- **세 레이어, 결정 하나씩.** 근거: 사용자 요구 2 (전경 → 목표·시작 → 강화 버튼). ui.md "중요도 차등에 따라 분리되어 보이게": 장을 고를 때 강화 칸이, 강화할 때 장 정보가 필요 없다.
- **가진 금화는 병영에서만.** 근거: 요청 원문 "각 자원이나 정보는 각 Scene에서 필요한 경우에만" 을 기획 에이전트가 이렇게 읽었다. 금화는 강화를 살 때만 쓴다. 출정에 드는 비용이 없어 장을 고를 때 가진 금화는 결정을 바꾸지 않는다. 장을 고를 때 필요한 것은 그 장이 줄 보상이라 L2 에 보상만 둔다.
- **병영 버튼의 "살 수 있는 강화" 배지.** 근거: 금화를 숨겨도 "지금 병영에 가면 살 것이 있다"는 알아야 한다 (progression.md "빌드를 고민"). 숫자 하나가 금화 숫자보다 그 결정에 가깝다.
- **표식은 UI, 지역은 3D 모형.** 근거: 고정 크기(ui-style.md 15)는 UI 라야 지킨다. 3D 표식은 카메라가 멀어지면 작아지고 소품에 가린다. 버튼·툴팁·키보드 초점을 그대로 쓴다. 3D 는 지역 모형·빛·스폿광으로 상태를 보인다.
- **이름 띠는 가리킨·초점·고른 표식만.** 근거: ui-style.md 14 "글보다 그림", Desperados III 는 고른 지점에만 이름 띠를 단다. 열 개 이름을 늘 띄우면 지도가 글로 덮인다.
- **↑ = 다음 장.** 근거: 지도에서 원정은 화면 위(북쪽)로 간다. 목록이 사라졌으니 방향은 지도를 따른다.
- **빈 땅을 누르면 L1.** 근거: Civilization VI 처럼 옆 칸은 지도를 누르면 닫힌다. L3 는 사고 있는 중이라 닫지 않는다.
- **오른쪽 칸 폭 560.** 근거: 영어 장 이름(가장 긴 "Village Below the Castle")이 `h.1` 한 줄로 400 폭에 들고, 칩 6개(434)가 들어간다. 1920 폭에서 빈 곳이 1288 남아 지역 모형이 가운데 넉넉히 보인다.
- **진행 초기화는 L1 에만.** 근거: 3단계(배경) 기능이고 오른쪽 위는 L2·L3 의 칸 자리다. 되돌릴 수 없는 일이라 고르기·사기와 떨어뜨린다.
- **B 단축키.** 근거: Barracks 머리글자. 언어를 바꿔도 같은 키.
- **전투 뒤 돌아오는 레이어.** 근거: 새 장이 열렸으면 지도에서 열린 길을 보여 주는 것이 원정의 보상이다. 졌거나 다시 한 판이면 같은 장 정보로 바로 다시 출정한다.
